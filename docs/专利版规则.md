### 2.2 结构总览：每方 45 点 = 5 行 × 9 列，共 135 点

**每方是一个"五边形领地"**：底线（六边形的一条边）+ 两条侧壁 + 最内层尖角（凸向中心）。

|---|---|---|---|---|
| row1 底线 | (0, −90.1046) | (±52.0219, −90.1046) | 52.02 | 13.0055 |
| row2 | (0, −71.8121) | (±57.8022, −80.0930) | 57.80 | 14.45 |
| row3 | (0, −53.5195) | (±63.5824, −70.0814) | 63.58 | 15.90 |
| row4 | (0, −35.2269) | (±69.3626, −60.0698) | 69.36 | 17.34 |
| row5 最内 | (0, −16.9343) | (±75.1428, −50.0581) | 75.14 | 18.79 |

**两个等量规律**（精确成立）：
- 中轴点每行位移 **18.2923**（向内）
- 半宽每行增量 **5.7807**（向外）
- 两端点恰好落在六边形的斜边上，沿斜边以 11.5615 步长移动

**每条行线是 V 形**（两端点在中轴点外侧，即"**底边向中心凸起**"）。
**列线**：9 条，从底线 9 点直连到 row5 对应点（直线）。

### 2.3 三条中心地带（赤壁 / 荆州 / 祁山）

每条地带 = 楔形，夹在相邻两方的"最内层（row5）外臂"之间：

| 地带 | 夹在 | 外端（宽 11.5615） | 内端 |

### 2.9 ✅ 战线直通（车 / 炮的跨方贯通纵线）

**原文依据**（规则图《二、棋子运行逻辑》第 2 条「棋盘纵向路线」）：

```
E(1：2：3：4：5)————O(9：8：7：6：5)；
E(5：6：7：8：9)————J(5：4：3：2：1)；
J(5：6：7：8：9)————O(5：4：3：2：1)；
```

E / J / O 都是**底线行（row1）**，两个底线点之间隔着整个棋盘 →
这条"纵向路线"必然是**跨方贯通直线**。

| 原文 | 底边数字配对 | 引擎（列号）配对 |
|------|------------|----------------|
| E(1..5) — O(9..5) | 魏图1↔吴图9 …… 魏图5↔吴图5 | 魏列9..5 ↔ 吴列1..5 |
| E(5..9) — J(5..1) | 魏图5↔蜀图5 …… 魏图9↔蜀图1 | 魏列5..1 ↔ 蜀列5..9 |

**判据**：任意一对的**底边数字之和恒为 10**。列5 是中轴，同时接两个对面方。

- 共 **15 条**贯通纵线（3 组 × 5 条）；引擎 `_front_lanes()` 去重后条数**完全一致**。
- **DXF 里只有 3 条**（"图1↔图9"那三对）真连成一条直线，最大偏离 **0.000**；
  其余 9 条接线在 DXF 中不存在，强行拼接最大偏离 **27.4 ~ 39.2**，而相邻格距仅 **11 ~ 20**
  → 它们是**规则共线**，不是几何共线。
- 规则图《一、9. 帅不见面》另列六条（列5 三条 + 列4/6 三条）作为"帅见面"判定线路 ——
  即本条的子集抽样（原图幅面太小，只画了靠中轴的两列，末尾用"（如图）"带过）。

**引擎实现**（`server/engine/rules_dxf.py`）：

```

_front_lane(a, c, b)                 # [本方 行1..行5 列c] + [对面 行5..行1 列(10-c)]
_splice_front_rays()                 # → SPLICE_STAT = (240, 30)
```

### 5.1 《一、3》不是"判定"，是「回合与步数」

- 之前文档把它记成"每回合可进行一次『判定』"是**误记** —— "判定"是《一、10》判负那个动作。

  网页「每回合步数」输入框可约定 1~20；`turn_steps` 记本回合已走步数。
- 不落子的动作（**判负 / 认输**）不计入步数（`_advance(s, moved=False)`）。

### 5.2 《一、7》副帅 = 「吃帅的棋子就地升格」

- 老师（**2026-09-25 最终口径**）：「**退回原先的方式**」—— 看回《一、7》第 7 条原文后
  确认**原文口径就是对的**。
- 原文：「A 帅被 B 的棋子吃掉，A 方剩余棋子归 B 控制，**吃 A 帅的棋子为 B 方副帅**，
  在 A 方"军帐（田字格）"内行使帅的运行方式和职责……」
- 语义：**吃帅的那枚棋子本身**升格为副帅（棋子在两方之间**改身份**，不是新造单位）：
  · 它吃掉 A 帅后落点 = A 帅原位置，就在该点"变身"为 B 方副帅；
  · **原棋子（炮/车/兵…）从盘上消失** —— 棋子数**净减 1**；
  · 三项自洽性：① 位置必在 A 军帐内 ⇒ 「副帅不能出军帐」自动成立；
    ② 与"副帅不可能阻隔帅见面"自洽（见 5.4）；③ 与《一、9》豁免 2 自洽。
- ⚠️ **前端必须把这件事讲出来**（老师 2026-09-25 明确要求）：
  战报用 `note.promoted_from`（升格前的棋子种类）显示「**炮→副帥**」。

#### 5.13.2 实现（`rules_dxf.snipe_targets`）

```python
def snipe_targets(board, pos, army, frozen=_EMPTY):
    out, seen = [], set()
    for path in RAYS.get(pos) or ():
        for q in path:
            t = board.get(q)
            if t is None:
                continue                    # 空点：视线继续延伸
            if (t["kind"] == GENERAL and t["army"] != army
                    and not (frozen and t["army"] in frozen)
                    and q not in seen):
                seen.add(q); out.append(q)  # ★ 射杀：照见即可吃
            break                           # 第一个子 —— 射杀或被挡
    return out
```

- 接在 `_general()` 里：**先**军帐内横竖 1 格（传统走法），**再**补射杀落点，
  用 `seen` 去重（相邻敌帅可能既走得到也射得到）。常规着法在前 ⇒ 着法表顺序稳定。
- **判据纯拓扑**，一个角度都不碰：`RAYS` 里各方自己的行线 / 军帐斜线都不跨方，
  只有跨方贯通线才可能把两帅串起来 ⇒ "扫第一个子"**精确等价于**"共线且中间无子"（= `line_of_sight`）。
- **强证据**：`tests/_verify_snipe.py` §4 穷举全部 135 点位的 **6075 个跨方点对**，
  `snipe_targets` 与 `line_of_sight` **100% 一致（0 不一致）**；中间插子后同样一致。

### 5.16 🆕 2026-10-02 · **每方主控：本地 Bot / API 大模型**（网页可选）

> ①「有没有可能选择让魏国给人类，另外两个接入 deepseek 和 hy4 api？」

#### 5.16.1 做了什么

四个 API 条目的状态是**实测出来的**，不是抄来的（见 5.16.8）：
**3 条能用**（DiffusionGemma-26B / Nemotron-3-Super-120B / Nemotron-3.5-Lightning-30B）

#### 5.16.2 为什么本地那一项**只有 `__search__` 一项**（没有"贪心Bot"）

因为「一步贪心」**已经由难度档 1「新手」表达了**（`difficulty.apply` 在档 1 会把
`model_id` 变成 `__local__`）。两个入口管同一件事 ⇒ 一定打架。故只留一个：
**想让它弱 ⇒ 调难度档，而不是在下拉里选贪心。**

> 不是"当前落到哪个类"）。→ 下拉才不会自己跳到不存在的项（有专项断言）。

#### 5.16.3 三条红线

1. **只换脑子，不动棋局**：棋盘 / 手数 / 轮次 / 战绩 / 悔棋次数 / 规则约定 / 人类接管 **一律不动**
   （与切难度档同一条口径）。专项测试连换 6 次席位后比对**对局指纹逐字段一致**。
2. **没配好就明确拒绝**：缺 `url`/密钥的 API 条目在下拉里 **置灰 + 写明缺什么**，
   后端 `set_seat` 也**拒绝**并说明原因 —— **绝不静默换成本地 Bot**
   （"选了没反应 / 悄悄换了模型"是最难查的一类 bug）。
3. **必须有"红线条约"**：网页换主控**只**允许发 `POST /api/seat`，
   整条链路**绝不允许**出现 `/api/move`、`/api/undo`、`/api/new`（换脑子 ≠ 替老师走棋）。

#### 5.16.4 目录放哪 · 怎么加模型（**不用改 Python**）

* 目录 = `server/agents/agents.json` 的 **`model_options`** 段；逻辑 = `server/agents/seats.py`。
* 密钥沿用 `llm.resolve()` 的**既有口径**（不另造一套）：条目自带的 `url`/`api_key`/`api_model` 优先，
  否则回落到 `~/.workbuddy/models.json` 里同 id 的那条。⇒ DeepSeek 只写 `id` 就能用。
* 加一个模型**三种**写法：
  * ① 只写 `{"id": "<models.json 里已有的 id>", "label": "显示名"}` —— 密钥自动取；
  * ② 写全 `{"id":"xxx","url":"…/chat/completions","api_key":"sk-…","api_model":"真实模型名"}` ——
    **密钥会落盘在本项目里**（这个项目有 GitHub 版，尽量别用这招）；
  * ③ ★ **推荐：`key_from` 借密钥但不落盘**。同一厂商一个 key 能开很多模型、
    而 `models.json` 只登记了少数几条时，写
    `{"id":"任意名", "label":"…", "key_from":"<models.json 里同厂商任一条的 id>",
      "api_model":"真正要请求的模型名"}`
    ⇒ 本项目里**一个密钥都不写**，改一行就能换模型。
    ⚠️ 用了 `key_from` **必须**同时写 `api_model`：`llm.resolve()` 是拿
    `cfg["model_id"]` 去 `models.json` 查 url/密钥的，所以 `apply()` 会把
    `model_id` 指向**凭据来源那条**；此时若不写 `api_model`，请求就会落到
    **被借那条的模型**上（**静默换模型**，最难查的一类）。`readiness()` 已加守卫，
    选之前就报错（有专项断言）。
* 改完**重启** app.py 生效；**前端不用动**（选项由 `/api/state` 下发）。
  ⚠️ **不要用 `POST /api/reload_agents` 热重载**：它 `MATCH = Match(LLM.load_roster())`
  —— **新建一个 Match**，等于丢掉老师正在下的那一局（且会立刻落盘盖掉存档）。
  只有老师明确要求"重开"时才用。

#### 5.16.5 席位跨重启保留（老师的显式选择 > 离线默认）

* 存档新增 `seats` 字段（`{1:"__search__",2:"…",3:"…"}`，记**选项 id**）；
  `restore()` 在 `apply_difficulty` **之后**重新套一遍席位。
* ⚠️ **必须在难度档之后**：换回本地 Bot 时要套上当前难度档，否则会掉回 `agents.json` 的兜底 depth。
* ⚠️ **`--local` 降级不再吃掉老师的席位**：`启动对弈台.bat` 用 `--local`，它会在启动时把
  "需要联网"的模型打回本地 Bot；但**恢复存档时会把老师的 API 席位装回来**。
  ⇒ 语义是「**老师的显式选择 > 离线默认**」（有专项断言）。
* 存档里记的席位**现在不可用**（例如密钥被删）时：不改其他东西，并往战报写一条
  「⚠️ 存档里的席位未能恢复」——**不静默降级**。

#### 5.16.6 性能口径（**别在快照里读磁盘**）

* `/api/state` 每 ~800ms 被轮询一次，而算 `readiness` 要读 `~/.workbuddy/models.json`
  ⇒ 下拉目录**必须缓存**（`Match._seat_ui`），只在 **构造 / `set_seat` / `apply_difficulty`** 三处刷新。
  有断言：**连续两帧快照返回同一个对象**。
* 前端也有对应的一条：**选项签名（`seatSig`）不变就不重建 `<option>` DOM**，
  否则每 800ms 重建一次会把老师正在展开的下拉打断、并丢焦点。
* `seats.py` 的 `catalog()` 容错：把 `model_options` **段本身**误传进来时能认出来 ——
  否则会**静默退化**成兜底目录（表现为"API 项明明配了却说找不到"，属最难查那类）。

#### 5.16.9 本轮踩到的三个真 bug（都已修 + 都加了防复发断言）

**① `catalog()` 把 `disabled` 静默剥掉了 ⇒ "显式停用"从来没生效过。**
`seats.catalog()` 用**白名单**逐键复制（`{k: it[k] for k in (...)}`），而白名单里没有
`disabled` ⇒ `readiness()` 里的 `opt.get("disabled")` **永远读不到**。
表现：**欠费的 DeepSeek 照样能在下拉里被选中**，然后每步失败。
> 教训：这类 bug 的特征是「**功能看着写好了，但被上一层静默过滤**」——
> 光读 `readiness()` 的源码抓不到，**断言必须走 `catalog()` 出口再读一遍**。

**② `key_from` 省下密钥，但忘了写 `api_model` 就会静默换模型。**
`llm.resolve()` 是按 `cfg["model_id"]` 查 `models.json` 的 ⇒ 借密钥必然把
`model_id` 改指到被借那条 ⇒ 不写 `api_model` 就会请求成**别人的模型**。
`readiness()` 加了守卫（判不就绪 + 写明原因），并有端到端断言
（`set_seat` 拒绝 + `seats` 不被写脏）。

**③ 推理型模型的 `max_tokens` 给小了 ⇒ 每步静默回退本地 Bot。**
首版给 `nemotron-3-super-120b` 配了 `max_tokens: 700`（照抄了 DiffusionGemma 的值），
结果**实战战报里出现**：
`{"model":"蜀方·Nemotron-3-Super-120B","latency":26.04,"fallback":true,
  "reason":"搜索3步(上限1层·JIT) 估值+22.9"}`
—— 即：**大模型调用失败 → 兜底 Bot 代走一步**，老师白等 26 s / 58 s。
根因：推理型模型先吐几千 token 推理，700 的额度被推理吃光 ⇒ 正文为空。
改成 **`max_tokens: 6000`** 后实测 20.2 s / 56.8 s、**2/2 合法**。
> 教训：**"回退"必须让老师看得见**。现在有两层可见性：
> 战报里那个红色 **「代走」** 标签（前端 `e.fallback` ⇒ `<span class="grade gr">代走</span>`）
> 和 `agents.py` 的 `illegal` / `legal_rate` 统计。**没有可见性的话，
> 这会是一个"看起来在下棋、其实大模型根本没接上"的隐形故障。**

### 5.17 🆕 2026-10-02（第四轮）· **反复走同一条路径：改成事前拦截**（「长将判负」退役）

> 老师原话（两段，第二段是**裁决**）：
> ①「长将判负：魏方反复走同一条路径（222-232）并且一直在将军，超过 3 次 →
>   依传统中国象棋「长将判负」，该方失去行棋资格（帅留盘、棋子不易主，≠ 出局）」
> ②「**不对，为何魏方被判出局，你只要限制它不走重复路径就 ok 了**」

#### 5.17.1 改了什么

| | 旧（2026-10-01） | **新（2026-10-02）** |
|---|---|---|
| 时机 | **事后判罚** —— 走完第 4 次才发现 | **事前拦截** —— 第 4 次**根本不在** `legal_moves` 里 |
| 长将 | 写 `out` + `declared_lose`（判负） | **什么都不写**，棋局照常继续 |
| 纯重复（不将军） | 判「不变作和」，对局结束 | 同上 —— 也能走出来被拦，不结束 |
| 唯一兜底 | 无 | 某方**除重复外无路可走** ⇒ 温和判「不变作和」 |

一句话：**从"走出去再罚"改成"根本走不出"**。

#### 5.17.2 为什么非改不可（这条是本次的核心）

前端 `web/app.js` 把 `status.out` **直接渲染成「已出局」**，两处：

```js
al.push('出局：' + st.status.out.map(k => ARMY[k] + '方').join('、'));
const gone = (st.out || []).includes(k);      // 已出局 / 已判负 / 已认输
```

而本项目「出局」的**唯一**触发条件是**主帅被吃**（`alive_armies` 的注）。
旧写法把「长将判负」也塞进 `out` ⇒ 老师屏幕上出现「**魏方被判出局**」——
连旧战报文案里那句「≠ 出局」都救不了，**因为前端只认 `out` 这个数组**。

> 📌 **通用教训**：一个字段承担两种语义（`out` = 出局 ∪ 判负），
> 那么只要有一处渲染按其中一种语义写死文案，另一种语义就会**显示错的字**。
> 引擎层的「语义分层」（`out` / `eliminated` / `declared_lose`）必须和
> **所有的渲染出口**对齐，否则分层等于没分。

#### 5.17.3 判据（三条，缺一不可）

* **无向边**：`edge_key(a,b)` ⇒ `222-232` ≡ `232-222`
  （老师现场就是**来回走**；只按有序 `(from→to)` 数就永远凑不满次数）；
* **同一方连续**：该方中间换了别的边 ⇒ 计数重置为 1（不误禁无关着法）；
* **超过上限**：`REPEAT_LIMIT = 3` ⇒ 允许走 3 次，**第 4 次不可选**；
  `repeat_limit = 0` ⇒ 整条规则关闭（保留给"只想观棋"的场合）。

#### 5.17.4 落点清单（七层）

| 层 | 文件 | 具体 |
|---|---|---|
| 判据 | `server/engine/game_dxf.py` | 🆕 `_repeat_limit` / `repeat_blocked` / `repeat_stuck` |
| 过滤 | 同上 | `legal_moves(..., skip_repeat=False)` 里拦截（**唯一业务出口**） |
| 兜底 | 同上 | `apply()` 末尾遍历**所有在局方** ⇒ `repeat_draw`（**绝不写 `out`**） |
| 退役 | 同上 | 删掉 `repeat_strike()`（会写 `out`/`declared_lose` 的那个函数） |
| 兼容 | 同上 | `repeat_state()` 同时认 `int` / `str` 键（存档往返会变 str） |
| 战报 | `server/match.py` | `_note_repeat_verdict()` 只产出 `draw`（判和），**不再产出 `judge`** |
| 门禁 | `tests/_verify_repeat_guard.py` | 🆕 **53 / 0**（9 节） |
| 探针 | `tests/_probe_repeat_guard.py` | 🆕 **16 / 0**（平行判据，**改前先跑应为红**） |

#### 5.17.5 「不误伤」的三条保证

1. 没有重复记录（开局）⇒ 着法**一个不少**；
2. 换了另一条边 ⇒ 计数重置 ⇒ 不误禁；
3. `repeat_limit = 0` ⇒ 规则整体关闭。
   门禁里三条都实测：关闭状态下可以连着走 5 次同一条边。

#### 5.17.6 侧面验证：人类玩家也走不出来

`manual_move()` 在落子前做同一套校验
（`legal = {f"{a}-{b}" for a, b in GA.legal_moves(s, s["turn"])}`，不在里面直接返回
`"xxx 不是合法着法"`）⇒ 网页上**那一手直接点不动**；
`/api/state.legal`（前端落点高亮）也来自同一个 `legal_moves`。
⇒ 老师、本地 Bot、API 大模型**三条路径同时生效**，不存在"人走得出、机器走不出"。

#### 5.17.7 本轮附带修掉的一个测试假失败

`tests/_verify_deputy_log.py` §③ 原本把**真实存档的内容写死**
（「ply27 是魏炮吃真帅 / ply28 是蜀車吃副帥」）—— 老师一重开新局就必然假失败
（2026-10-02 实测 **22 / 1**）。改成**按语义挑样本**（谁吃真帅、谁吃副帥由存档自己说了算，
某类不存在就跳过），并且刻意带 `if 守卫`：**样本为空时 `all([])` 恒为 True ⇒ 假绿灯**。
改后 **23 / 0**，且不再依赖具体手数。

> 📌 **教训**：测试**不许把生产数据的内容写死**。凡是读真实存档/真实输出的断言，
> 要么只断"结构"（字段在不在、类型对不对），要么**按语义动态挑样本**。
