## V0.1 · 引擎骨架与 DXF 变形棋盘

**改了什么**

- 棋盘不是标准象棋盘，而是**三方 Y 形拼合**的变形网格（135 个点，开局 48 子）。
- 建立 `geometry_dxf`（点位/邻居/坐标标签）与 `rules_dxf`（7 张走法表 + 射线表 + 见面线）。

**为什么改（根因）**

- 原图 `docs/专利版棋盘原图.jpg` 顶边字母是**旋转 180° 印**的（肉眼读成 `O N M L K`），
  必须高倍裁切才能读对。
- **格距 13~24 不等**（DXF 变形）⇒ **长度与夹角没有任何判据意义**。
  这一条后来变成最高优先级的铁律，代价是铲掉了一批用几何角度写的判据。

**被什么守住了**

- `ANG_TOL` 不许放宽：最大折角 **47.58°** > 方向族最小夹角 **35.412°**，
  一旦用角度判共线，两者会串味。
- `tests/_verify_rays_topology.py` 带 **AST 扫描**，防止已铲的
  `_same_line / _same_angle / _leg_rank` 被重新写回来。

**关键常量**

```
LETTER      = {1:'ABCDE', 2:'KLMNO', 3:'FGHIJ'}        # 魏 / 吴 / 蜀 的行字母
coordLabel  = LETTER[army][5-row] + (10-column)        # 引擎号 → 棋盘标签
ARMY_CN     = {1:'魏', 2:'吴', 3:'蜀'}                  # ⚠️ 权威值（曾被写反过）
TRI_PTS     = {155, 255, 355}                          # 三角区三格点
```

## V0.2 · 专利版三态规则（军帐 · 副帅 · 生命力/战斗力）

**改了什么**

| 概念 | 定案 |
|---|---|
| **军帐** | 每方九宫 3×3＝9 点，中心＝`{army}25`（魏 D5 / 吴 N5 / 蜀 I5） |
| **副帅** | 主帅被吃 ⇒ 该方残兵归吃帅方，**吃帅那枚棋子就地升格**为副帅，驻被斩方军帐 |
| **生命力** | 二值：本方主帅是否在盘上（副帅不算主帅） |
| **战斗力** | 二值：主帅在，或手里握着别方副帅；**已失去行棋资格者恒为 False** |
| **出局 `eliminated`** | **唯一触发 = 主帅被吃**（不含判负、不含认输） |
| **《一、10》判负** | 帅被动见面 ⇒ 判负（帅留盘、棋子不易主）—— *V0.3 已退役* |
| **残局自动判平** | 只剩象/士 + `STALEMATE_ROUNDS = 9` 轮 + 帅不照面 |
| **认输** | 不存在"求和"，只允许认输（帅留盘、棋子不易主） |

**为什么改（根因）**

- 老师 2026-09-24 明确：「生命力/战斗力**只有有/无**，不需要具体数值」。
- 「出局」若把判负也算进去，前端会把"判负"渲染成"被斩帅"（后证实确有此事，见 V0.7）。

**被什么守住了**

- `test_dxf.py`：**106 项**，含"三方出局两方后终局判定"、"前一手拿到的副帅随原控制方出局一并易主"。
- `_verify_rule9_10.py`：**52 项**，专测《一、9》第 3 条"独占口径"四情形。
- `_verify_deputy.py` / `_verify_deputy_log.py` / `_verify_fix_pawn_slain.py`。

**踩过的坑（都留了注释）**

- ❌ 军帐"米字格"误把**对角线**也算进共线 ⇒ 军帐内共线对虚高。
  修法：`RAYS` 层加 `_is_tent_diag / _drop_tent_diag`，**在缝合之前**且**滤空 tuple**；
  JIT 零改动。修完军帐内共线对＝**108**。
  ⇒ 铁律：**"哪些点共线"一律以 `RAYS` 实测枚举为准，不照抄文档。**
- ❌ 吃副帅时误写 `note["eliminated"]` ⇒ 三个连锁后果：
  ① `slain[army] += 1` ⇒ 综合分凭空 **+1000**（`W_SLAIN`）；
  ② 前端三元链 `e.eliminated ? 斩帥X方主帅 : …` 优先命中 ⇒ 渲染成"斩主帅"；
  ③ 屏幕提示该方"被杀出局"（其实它早就出局了）。
  修法：`game_dxf.apply()` 里按 `victim.get("deputy")` 分流成 `note["is_deputy"] = True`。

## V0.3 · ★ 照见即可射杀（规则大改）

**改了什么**

| 项 | 旧（《一、9》禁止照面 + 《一、10》被动判负） | 新（2026-09-25 老师定夺） |
|---|---|---|
| 帅照面 | 违规 ⇒ 被动方判负 | **合法**，且**轮到谁，谁就能吃** |
| 谁能射杀 | — | **主帅与副帅同权** |
| 打谁 | — | 只能射杀对方**帅 / 副帅**（普通子挡在线上则打不动、也不穿透） |
| 线路 | — | 沿**见面线**（规则图上那六条跨方贯通线） |
| 后果语义 | 判负（帅留盘） | **吃子**：对方帅从盘上消失 ⇒ 该方出局 + 残兵易主 |

**为什么改（根因）**

- 老师原文：「魏国控制的副帅已经照见 I5 的主帅，并且这时轮到魏国走，
  **为何魏国控制的副帅不能射杀 I5 的主帅**」。
- 推论链：既然照见即可射杀，则"禁止照面"与"被动判负"两条同时失去意义 ⇒ 一并退役。

**被什么守住了**

- `tests/_verify_snipe.py`（**72 项**，9 节），其中两条是最强的：
  - §4 **跨方穷举等价**：全部 135 点位、**6075 个跨方点对**，
    `snipe_targets` 与 `line_of_sight` 判据 **100% 一致**（含"中间插一子"的对照）。
  - §9 **副帅当射手**（2026-10-02 补）：老师那局 `ply 64` 的真实点位 `225 → 115`，
    逐字段复现战报 `{captured:'general', eliminated:1, is_deputy:False}`。
- §1 的对称性穷举：军帐内"跨方可照见"恰 **54 对**（27 对 × 双向），
  起点列只落在 **4 / 5 / 6**，其中列 5 占 **27 条**。
- §5/§6 源码级断言：`legal_moves` 已删除"试走 clone"式见面过滤、
  不再引用 `pending_judge`（被动见面待决已退役）。

**顺带定案的边界**

- 《一、9》第 3 条"独占口径"保留：只有**独占照见**的一方有资格吃「已出局方的帅」；
  多方争抢（三点共线）⇒ **谁都不得吃**。

## V0.4 · 对弈台 + 难度档 + 坐标标签

**改了什么**

- `server/app.py`：HTTP 接口（`/api/state` `/api/move` `/api/hint` `/api/undo` `/api/replay` …）。

- **难度档 4 级**：新手 0 / 入门 3 / 进阶 6 / 大师 9 plies，默认第 2 档。

**为什么改（根因）**

- 老师：「bot 挑战难度档位可以在网页里面选择，默认选第二档」。
- 引擎点位号（`245-125`）人看着费劲 ⇒ 一律显示坐标标签 + 简体中文棋子名。

**被什么守住了**

- 前端 DOM 桩测试（**真触发事件看回调**，不只看字符串）：
  `_verify_resume_ui.js`(21) · `_verify_replay_ui.js`(57) · `_verify_hint_ui.js`(89) ·
  `_verify_undo_rescue_ui.js`(15) · `_verify_check_alarm.js`(48)
- 前端测法（**固定套路**）：IIFE 尾 `})();` 换 `window.__t={…}; })();` 再 `eval`
  （**只改内存字符串**）+ 最小 DOM 桩（须实现**元素级** `querySelectorAll`）。

**踩过的坑**

- ⚠️ **模块级缓存在 `init()` 必须清零**：`_triActive / _lastHint / _lastHints / _lastFocus`
  —— 否则"重开一局后新棋盘上的标记永不激活"。
- 🔴 **静态资源防缓存**：`?v=__STAMP__` → 启动时间戳；`/api/state` 返回 `build`，
  前端发现不一致自动 `location.reload()`（≤3 次）。否则改了前端老师那边"没变化"。
- 视觉口径：棋盘文字＝**纯单层彩色字**（只 `fill`、`stroke:'none'`、`font-weight:'normal'`）。
  `bold` + 同色描边 = 笔画加肥两层。代价是压同色棋子会吞笔画 —— **老师已认可**。
- 视觉改动的**唯一硬标准 = 截真实网页**（`tests/_shot_tri.js` / `_shot_label.js`，
  puppeteer-core + 本机 Chrome），截前 `animation:none` 冻帧 + 回读 `getComputedStyle`。

## V0.5 · AlphaZero 化第一步：特征 + 价值网络

**改了什么**

| 文件 | 作用 |
|---|---|
| `server/agents/features_dxf.py` | **32 维特征**（旧 10 项 + **新增 12 维"子力安危"**） |
| `server/agents/value_net.py` | `LogiNet`（线性，可解释）+ `MLPNet`（2 隐层，能打），纯 CPU 训练 |
| `tests/_train_value_net.py` | 本机自对弈训练管线（单进程，几百局调试用） |

**为什么改（根因）—— 本版本最重要的一段**

老师报了一个 bug：推荐引擎让魏右车 `E9→D9` 前进一步，结果魏马 `E8` 被蜀炮 `H2` 白打。
查根因时挖出一个**原理性结论**：

> **换 AlphaZero 治不好"送马"。**
> value head 只是「特征 → 胜率」的映射；**特征里没有"我的子正被白吃"这一维，网络就学不出来。**

实测证据（同一个局面）：

| 局面 | 旧 `eval` 对魏方评分 | 新特征"悬子值" |
|---|---|---|
| 开局，车 E9 保着马 E8 | **+36.96** | 0.0 |
| 车走 `111→121`（车让开、马无人保） | **+37.87（反而涨了）** | **4.0（一个马的整价）** |

攻击者名单的变化是客观事实、不依赖任何权重：
```
开局   ：112(E8 魏马) 的攻击者 = [E9 魏车（自己在保）, H2 蜀炮]
停车后 ：112(E8 魏马) 的攻击者 = [H2 蜀炮]        ← 唯一的保护者让开了
蜀方合法着法里能吃 112 的：H2→E8（确实存在）
```

⇒ **瓶颈不是算法，是"这一维根本不存在"。** 所以第一步是**补特征**，不是换算法。

**旧 `eval_dxf` 的 10 个计分项（全部与子力安危无关）**

| 项 | 权重 | 它测什么 | 能表达"马被白吃"吗 |
|---|---|---|---|
| `pressure` | 0.250 | 我压向敌帅的压强（**√子力加权**） | ✗ |
| `danger` | 0.100 | 敌压向我的压强 | ✗ |
| `urgency` | 0.050 | 进攻权重随时间上升 | ✗ |
| `material` | **0.100** | 我 − **最强的那一个**对手 | ✗（权重极低 + 只跟最强比） |
| `check` | 120.0 | 将军 | ✗ |
| `close1` / `close2` | 400 / 80 | 有子贴到敌帅 1 / 2 步内 | ✗ |
| `mobility` | 0.02 | 可走着法数 | ✗ |
| `deputy` | 6.0 | 手握副帅 | ✗ |
| `gen_lost` | 50.0 | 自家帅没了 | ✗ |

**这是"我想不想快点击杀敌帅"的模型，不是"我的子会不会丢"的模型。**

**被什么守住了**

- 稳健性自检（**踩坑后加的，现在是上线门槛**）：用开局 44 手合法着法两两比较，
  特征 L∞ < 0.10（肉眼几乎一样）却给出 |ΔP| > 0.05 ⇒ 记一次"矛盾"。

| 模型 | 矛盾对数 | 判决 |
|---|---|---|
| `logi` | **0 / 946** ✅ | 过 |
| `mlp`（800 局版） | **148 / 946** ❌ | **不许上线** |

- ⇒ 门槛写死：**`val auc ≥ 0.80` 且 `mlp` 稳健性矛盾 ≈ 0**，两条同时满足才许上线。

**踩过的坑**

- ❌ 标准化放大：特征已手工归一化，再除以 batch std 会把"几乎不变的维度"放大几十倍
  ⇒ 加 `SD_FLOOR = 0.10` 把最大增益锁在 10 倍内（同一对的 P 差 **0.208 → 0.061**）。
- ❌ 小样本会让系数翻符号：`my_hanging_val` 在 24 局里学成 **+4.72**，
  800 局才回到 **−3.27**。⇒ **不是算法问题，是数据量问题**（这正是云端要解的）。

## V0.6 · ★ 云端训练线 + A/B 裁判（投入最大的一版）

**改了什么**

三层架构，全在 `tools/`：

```
cloud_autopilot.sh           ← 调度层（90s 心跳：看进程、看 GPU、补拉起）
   ├── cloud_selfplay.py     ← 数据层（N worker 自对弈 → data/*.parts/partNNNNN.npz）
   └── gpu_daemon.py         ← 训练层（读全部 .parts → 训多档 → 选 best → 门禁 → 落盘）
            └── arena_gate() ← 裁判层（调 tools/ab_match.py 跑 300 局固定标尺）
```

云端机型：**AutoDL RTX 3090 24G · 15 vCPU（Xeon 8358P）· 90 GiB RAM**。

**产出（目前唯一在役的冠军）**

```json
{
 "name": "mlp_512_256", "hidden": [512, 256], "epochs": 400, "batch": 16384,
 "auc": 0.639,          // 冻结尺子下重测值（旧漂移尺子下是 0.6467）
 "auc_by_src": { "sp2.parts": 0.5566, "selfplay_150k.parts": 0.6537 },
 "bad_pairs": 0, "cmp_pairs": 363,
 "samples": 11105318,
 "md5": "8b32d63bc0830950a8f996950c8d8d43", "bytes": 3539592,
 "yard": { "ordi": 234, "wins": 160, "games": 300, "seed0": 2200000 }
}
```

**为什么改（根因）**

- 老师的指令链：「要尽量优化三人象棋的棋力」→「autoDL 有 GPU 和 CPU，GPU 基本空置，要好好运用」
  →「动手修根因」→「A/B 对局开干」。
- 核心洞察：**"棋力优化"这件事本身缺少裁判**。此前只有 AUC 一个尺子，而 AUC 已被三次独立实测
  证伪（详见技术总结 §四）。

**抓到的 6 个真 bug（每个都足以让整晚白跑）**

| # | Bug | 后果 | 修法 |
|---|---|---|---|
| 1 | ★★★ **尺子每轮漂移** | 守护连 6 轮 AUC 单调下滑，冠军永远不可达 | 冻结验证集 `val_frozen.json` + 冠军带 `val` 指纹 + AUC 降级为筛子 |
| 2 | **冠军随重启归零** | 下一轮无条件覆盖正式权重 | `champion.json`（带 `md5`）+ 启动时按指纹接手 |
| 3 | ★★ **autopilot 活锁** | 把门禁（纯 CPU）当成"GPU 卡死"腰斩守护 ⇒ `round` 永远停在 1 | 豁免锁 `gate.lock` + 陈旧锁兜底 + 打印真实耗时 |
| 4 | **`load_champion` 是死代码** | 定义了、单测全绿、**零调用点** | 补调用点 + `_probe_champion.py` 的 **AST 扫描** |
| 5 | **冻结验证集吃光训练池** | 打出 `验证 52,182 / 训练 0`，AUC 掉到 0.503 | 改"按片均行数估片数 + 片轴等间距取" |
| 6 | **GPU 被 CPU 饿住** | GPU 均值 25.2%，训练轮次变慢 | WORKERS 14 → 8（见下） |

**资源账（实测，非标称）**

| 项 | 实测值 |
|---|---|
| GPU 占空比（`WORKERS=8` 稳态） | **96.2%**（峰 100%，**344 W / 350 W**） |
| GPU 占空比（`WORKERS=14`） | **25.2%**（峰 76%，215 W） |
| 数据吞吐 | 8 worker **5.33 局/秒** vs 14 worker **5.69 局/秒**（**只差 6%**） |
| 自对弈并行效率 | **约 21%**（14 进程 4.6 s/局；单进程 0.98 s/局） |
| 单轮训练耗时 | `mlp_512_256` **253~267 s** / `mlp_1024_512` 294~320 s / `mlp_2048_1024` 784 s |
| 单次门禁耗时 | **381 s**（第一次） / **267 s**（第二次）——300 局，纯 CPU |
| 总样本 | **12,364,743**（`sp2.parts` 1,427 片 / 71,350 局 + 老数据 1,130 片） |

> ⚠️ **"充分运用 GPU"的正确姿势不是堆核**：14 个 CPU worker 把 GPU 从 96% 挤到 25%，
> 而吞吐只掉 6% ⇒ 多出来的 6 个核在互相抢内存带宽，纯属白扔。

**裁决结果**

- 价值网络确实更强：对纯搜索 **5 个 seed 批次 5/5 同向**，序数合计 **641 : 378**（n=1019，p≈1e-16）。
- 落地方式：**按座位配**（吴方开 λ=0.35，魏/蜀显式关）—— 依据见技术总结 §五。
- 两轮真实门禁判决：**Δ−7 / Δ−31，全拒**；冠军从 13:33 到收场**未被替换**。

## V0.7 · 对弈台交互修复 + 推荐档位（当前版本）

### 7.1 终局悔棋自救

**改了什么**

- `undo_last()` 开头原来是 `if self._finished(): return "对局已结束"` ——
  **终局后一律不许悔棋**，这就是老师看到的"悔棋键禁止点击"。
- 现在改为**终局自救**分支：主帅被斩的一方只要还剩机会，允许退回**自己上次落子前**
  （＝被将军之前）重走；悔棋后 `winner` 清空、对局复活。
- 新增 `_rescue_army()`：判据只有一条 —— **`eliminated` 里的最后一方**
  （＝造成当前终局的那一方），且它剩下的机会 > 0、且快照链里确有它的落子。
- 前端禁用条件：`!(allow_undo && can_undo && !finished)`
  → `!(allow_undo && can_undo && (!finished || undo_rescue))`。

**为什么改（根因）**

- 老师：「虽然是游戏结束了，但是魏国还剩一次悔棋机会，**应该允许魏国退回到将军之前**」。
- 第一版写成"从被斩方里往回找第一个还有机会的"，探针当场抓到荒唐结果：
  魏方机会用完后一点悔棋，**更早出局的吴方退了 34 手**。已改成只认最后被斩的那一方。

**没有开后门（三种情形仍拒）**

| 情形 | 结果 |
|---|---|
| 判和 / 超时终局 | 拒绝（没有"将军之前"可言） |
| 被斩方机会已用完 | 拒绝 |
| 胜方点悔棋 | 拒绝（撤回自己的取胜手无意义） |

**被什么守住了**

- `tests/_probe_undo_rescue.py`（**59 项**）：**内存自建局面**，
  走真实产线路径（`manual_move` → 推快照 → 落子 → 记战报）。
- `tests/_verify_undo_rescue_ui.js`（15 项）：真跑渲染确认按钮可点，真点一次确认发得出 `POST /api/undo`。
- ⚠️ 第一版探针直接拷 `server/data/autosave.json` 当夹具，结果老师在对弈台上玩了两手
  （ply 64→65、点掉悔棋机会），探针立刻 **16 条失败** ⇒ **已改成内存自建，不再依赖实时存档**。

**顺带挖出的既有 bug**

- 存档里的快照经 JSON 往返，`{1: 0}` 变成 `{"1": 0}`；读回时没归一化，
  悔棋回滚后 `snapshot()` 直接崩 `KeyError: 1`。
  以前从未暴露，因为过去都在**同一进程内**悔棋（快照是刚生成的、键还是整数）。
  **"重启续局 + 终局悔棋"是第一条必然跨存档使用悔棋快照的路径。**
  修法：`_norm_snap()`，并钉进探针防复发。

### 7.2 副帅登记表去残留（幽灵副帅）

**改了什么**

- 新增 `patent.prune_deputies(s)`：注销「盘上已无对应副帅」的登记条目。
- `refresh_combat()` 先调它、再按**收敛后的 owners** 算战斗力。
- `restore()` 读档后调它一次（**只修账本，不重算 vitality/combat**）。

**为什么改（根因）**

- `deputies` 是**派生表**（`{代表方: {pos, owner}}`），唯一真相是**盘面**。
  当"副帅自己跑去斩帅、就地升格为代表新方的副帅"时（老师那局 ply 64：
  驻吴帐的蜀方副帅 `225` 射杀魏帥 `115`），旧登记 `{2: …}` 无人注销 ⇒
  **盘上只剩 1 枚副帅、登记表却有 2 条** ⇒ 前端状态条多显一条**幽灵副帅**
  （"吴方军帐（归蜀）"，可吴军帐里早已没有副帅）。
- ⚠️ 判据**不能用 `pos`** —— 副帅在军帐内走动后 `pos` 从不更新
  （全工程无任何一处维护它），拿它当判据会把**活着**的副帅误注销。

**被什么守住了**

- `tests/_probe_deputy_ledger.py`（**18 项**）：
  - §1 四条定向路径（副帅射帅 / 副帅被吃 / 副帅走动 / 握副帅方被斩）；
  - §2 **60 局随机对局、5389 步，每步断言"账本 == 盘面"**；
  - §3 ★ **证伪自检**：把 `refresh_combat` 换回修复前的版本，断言**确实**留下 2 条 —— 证明探针抓得到真问题。
- `_verify_snipe.py` §9 同步断言账本一致性 + 负向自检。

### 7.3 推荐档位：默认 12 → **9 plies**

| 位置 | 旧 | 新 |
